# Security Policy

## Reporting Security Vulnerabilities

If you discover a security vulnerability in NetRange, please do **NOT** open a public issue. Instead, please report it responsibly by:

1. **Email**: Report security issues to the project maintainers
2. **Do not disclose publicly** until a fix has been released
3. **Include details** about the vulnerability and how to reproduce it
4. **Allow time** for the maintainers to develop and release a fix

## Security Considerations

### Authorized Use Only

NetRange is designed for legitimate security testing and network reconnaissance activities. Users are responsible for:

- **Obtaining proper authorization** before testing any networks or systems you do not own
- **Complying with all applicable laws** in your jurisdiction
- **Understanding legal implications** of network scanning and IP enumeration

### Potential Legal Issues

Unauthorized network scanning may violate:
- Computer Fraud and Abuse Act (CFAA) in the United States
- Similar laws in other jurisdictions
- Terms of service of network operators
- Organization policies and procedures

### Best Practices

1. **Only scan networks you own or have explicit written permission to test**
2. **Keep records** of authorization and testing scope
3. **Inform relevant parties** before conducting scans
4. **Use responsibly** and with minimal impact
5. **Clean up** after testing (e.g., remove output files)

## Responsible Disclosure Timeline

1. **Upon receipt**: Vulnerability is acknowledged
2. **Within 48 hours**: Initial assessment completed
3. **Within 7 days**: Fix development begins
4. **Upon release**: Public disclosure timeline discussed with reporter

## Acknowledgments

We appreciate security researchers who responsibly disclose vulnerabilities. Depending on the severity and nature of the disclosure, contributors may be acknowledged in the project documentation.
